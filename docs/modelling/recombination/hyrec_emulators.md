# Predicting $T_k$ and $x_e$ with HYREC-2 and astroemu

## HYREC-2

Computing the 21-cm signal requires the free electron fraction $x_e$ and gas
kinetic temperature $T_k$ as functions of redshift. These are produced by
[HYREC-2](https://github.com/nanoomlee/HYREC-2), a C code that solves the
full recombination history of the universe.

HYREC-2 is a C code and cannot run on a GPU. This is a fundamental
incompatibility with hyprfine, which is built on JAX and designed to run the
full 21-cm signal calculation on GPU hardware. Keeping HYREC-2 in the
pipeline would mean transferring data between CPU and GPU at every likelihood
evaluation, negating the performance benefits of GPU acceleration and
preventing end-to-end differentiation through the signal model.

We replace HYREC-2 with a pair of small neural network emulators — one for
$x_e$ and one for $T_k$ — trained on a grid of HYREC-2 outputs (roughly 5000 models)
spanning the cosmological parameter space. The emulators are pure JAX, run natively on
GPU, and are fully differentiable, enabling gradient-based inference through
the complete signal pipeline.

## Training data

Training samples were generated by running HYREC-2 across a random sample
of cosmological parameters:

| Parameter | Description | Range |
|-----------|-------------|-------|
| `H0` | Hubble constant (km/s/Mpc) | 20 - 100 |
| `Omega_b` | Baryon density | 0.005/h$^2$ - 0.1/h$^2$ |
| `Omega_c` | Cold dark matter density | 0.001/$h^2$ - 0.5/$h^2$ |
| `Y_He` | Helium mass fraction | 0.1 - 0.4 |

Outside of these parameter ranges the emulators and therefore `hyprfine` are unreliable. 
Each sample produces a full redshift history of $x_e$ and $T_k$.

The training data was generated using the UKRI Access to High Performance Computing Autumn 2024 grant
"APP63640 s(t)emu: Next generation emulators for cosmology and astrophysics".

## Network architecture and training

The emulators are trained using [astroemu](https://github.com/htjb/astroemu),
a library for training spectrum emulators with JAX. The training script can be found in
`bin/astroemu-hyrec.py`.

Each emulator is a multilayer perceptron (MLP) that takes a single redshift
value concatenated with the four cosmological parameters as input and returns
the corresponding $x_e$ or $T_k$ value. The full redshift history is recovered by
evaluating the network across the redshift grid.

The architecture and training configuration can be found in `bin/astroemu-hyrec.py`.

**Normalisation.** All inputs and outputs are log10-transformed then
standardised to zero mean and unit variance before training. The
normalisation statistics are computed on the training set and saved with
the emulator weights.

**Train/val/test split.** 80% training, 10% validation, 10% test.

## Trained emulator files

The trained emulator weights and normalisation pipelines are saved as
`.astroemu` files and shipped with the package under `hyprfine/data/`:

```
hyprfine/data/hyrec_xe.astroemu
hyprfine/data/hyrec_tk.astroemu
```

These are loaded automatically on the first call to `generate_signal` and
cached in memory for the lifetime of the process.

## Use in `hyprfine`

The HYREC-2 emulators are used to predict $x_e$ and $T_k$ down to redshift
$z = 50$ in `hyprfine`. At lower redshifts we solve a pair of couples 
ODEs for $T_k$ and $x_e$ using the values from the emulators at $z=50$ as our 
initial conditions. We do this so that we can include effects from the first stars and
galaxies on the evolution of the two quantities. This is discussed more [here](docs/modelling/recombination/cosmic-dawn.md).
In order to include the effects of the first stars and galaxies we need to estimate the total
Lyman-$\alpha$ and X-ray fluxes at a given redshift which we discuss [here](wouthuysen.md) and
[here](xrays.md).
